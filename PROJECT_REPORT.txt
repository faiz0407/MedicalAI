1. SYSTEM OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

HealthcareAI is a full-stack AI-powered healthcare assistant that combines a
Next.js 14 frontend with a FastAPI backend, 5 specialised LangChain agents,
a RAG (Retrieval-Augmented Generation) medical knowledge base, and multi-layer
persistent storage.

TECH STACK
  Frontend  : Next.js 14 App Router, TypeScript, Tailwind CSS, Zustand
  Backend   : FastAPI (Python), SQLAlchemy async (PostgreSQL)
  LLM       : Anthropic Claude Sonnet 4.6 (agents) + Haiku 4.5 (intent router)
  RAG       : BioBERT (local 768-dim embeddings) + Pinecone (483k PubMed vectors)
               + Cross-Encoder reranker (ms-marco-MiniLM-L-6-v2)
  Agent SDK : LangChain 0.3.x (create_tool_calling_agent + AgentExecutor)
  DB 1      : PostgreSQL — users, appointments, blog posts, audit logs, summaries
  DB 2      : AWS DynamoDB — chat sessions + messages (free tier)
  Payments  : Razorpay (mock mode active; real keys configurable)
  Email     : SMTP (mock fallback active; real SMTP keys configurable)
  Auth      : JWT (access tokens) + optional Google OAuth
  Container : Docker Compose (frontend + backend + postgres services)

NOTE ON PINECONE / RAG:
  Currently, "Source: PubMed" in responses is from the MOCK FALLBACK, not real
  chunks. The mock returns generic text with doi="" and pmc_id="", causing the
  citation builder to default to "Source: PubMed". RAG scores in the frontend
  (0.900 / cross: 0.000) are hardcoded mock values. Real chunks would show
  variable cosine similarity and non-zero cross-encoder scores.

  To enable real RAG:
    1. Set PINECONE_API_KEY in .env
    2. Re-enable BioBERT warm-up in main.py (uncomment the warm-up call)
    3. Rebuild: docker-compose up --build

8. AGENT DETAILS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

MASTER AGENT (master_agent.py)
  Role     : Intent classification + routing
  LLM      : Claude Haiku 4.5 (fast, cheap)
  Input    : User message + last 5 messages of chat history
  Output   : Intent string → routes to sub-agent
  Intents  : medical | appointment | reputation | content | notification | general
  Special  : CRITICAL BOOKING RULE — short affirmatives ("yes", "ok", "book it")
             after a medical/booking conversation are always classified as
             "appointment" to avoid misrouting

AGENT 1 — Medical Guidance (agent1_medical.py)
  Role     : Answer medical questions with evidence-based responses
  LLM      : Claude Sonnet 4.6
  Tools    : query_medical_knowledge (RAG pipeline), check_emergency
  RAG      : BioBERT → Pinecone → Cross-encoder → top-5 PubMed chunks
  Output   : Citation-grounded response + rag_sources list for frontend panel
  Max iter : 6 | Max tokens: 1024 | History: last 10 messages

AGENT 2 — Appointment Booking (agent2_appointment.py)
  Role     : Book appointments through conversational flow
  LLM      : Claude Sonnet 4.6
  Tools    : check_available_slots, create_appointment_booking,
             process_mock_payment
  Special  : Injects today's date so time references ("tomorrow") are correct
  DB Write : chat.py extracts booking_data from intermediate steps and calls
             crud.create_appointment() + crud.update_appointment_payment()
  Max iter : 6 | Max tokens: 768

AGENT 3 — Reputation Management (agent3_reputation.py)
  Role     : Monitor reviews, generate AI replies, flag problematic content
  LLM      : Claude Sonnet 4.6
  Tools    : get_reviews, generate_reply, flag_review
  Workflow : Negative reviews → AI reply → admin approves → posted
             High-risk keywords → flag → admin review
  Max tokens: 1024

AGENT 4 — Content Generation (agent4_content.py)
  Role     : Generate blog posts, social media content, website copy
  LLM      : Claude Sonnet 4.6
  Tools    : fetch_health_news, generate_blog_post, save_blog_post
  Workflow : News → AI content → saved as draft → admin approves → published
  Max tokens: 2048

AGENT 5 — Drug/Treatment Notifications (agent5_notification.py)
  Role     : Alert relevant patients about new treatments/drugs
  LLM      : Claude Sonnet 4.6
  Tools    : find_relevant_patients, generate_notification_email, create_campaign
  Workflow : Doctor triggers → agent finds patients by disease keyword →
             generates email template → creates campaign (pending) →
             admin approves → bulk email sent in background
  Max tokens: 1024

9. SECURITY & AUTH
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Authentication   : JWT (HS256) — access token in Authorization: Bearer header
Role System      : patient | doctor | admin
Route Guards     : require_admin, require_doctor decorators on sensitive endpoints
Audit Trail      : Every significant action logged to audit_logs table with
                   user_id, action, resource, resource_id, timestamp
Password Storage : bcrypt hashed (passlib)
CORS             : Configured per ALLOWED_ORIGINS env var

ROLE PERMISSIONS:
  patient  → own appointments, chat, feedback, reschedule requests
  doctor   → all patient appointments (read), update appointment status
  admin    → everything + user management + approval queues + audit logs

10. APPOINTMENT LIFECYCLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  [Chat] Patient tells Agent 2 to book appointment
      ↓
  Agent 2 confirms details (department, date, time)
      ↓
  create_appointment_booking tool called → POST /api/appointments/book
      ↓
  Appointment created in DB (status=pending, payment_status=pending)
      ↓
  process_mock_payment tool called → Razorpay mock order + verification
      ↓
  Payment confirmed → status updated (payment_status=paid)
      ↓
  Confirmation email sent (SMTP / mock)
      ↓
  Patient wants to reschedule?
      ↓
  POST /api/appointments/{id}/reschedule → RescheduleRequest (status=pending)
      ↓
  Admin reviews at GET /api/admin/reschedule-requests
      ↓
  Admin approves → appointment updated → status=confirmed
  Admin rejects → appointment unchanged → patient notified via admin_notes
      ↓
  Day of appointment: Doctor updates via PUT /api/appointments/{id}/status
      → showed_up → status=completed
      → no_show   → status=no_show + email sent to patient
      → cancelled → status=cancelled
      ↓
  Patient submits feedback via POST /api/appointments/{id}/feedback (rating 1–5)

  # Frontend : http://localhost:3000
  # Backend  : http://localhost:8000
  # API docs : http://localhost:8000/docs

  Default admin login: username=admin | password=Admin@123

  # View PostgreSQL data
  Open http://localhost:5050 (pgAdmin)
  Host: postgres (Docker service name — NOT localhost)
  Port: 5432
  DB: healthcareai
  User/Pass: from DATABASE_URL in .env
